# FlakeRadar

Маленький инструмент для поиска flaky-тестов: гоняет тестовый набор N раз
подряд в одном процессе и считает, какие тесты иногда падают, иногда нет,
сколько это занимает по времени и какие тесты падают вместе чаще, чем можно
было бы ожидать случайно.

## Зачем это

На одном из проектов раз в пару недель CI падал на тестах, которые "просто
иногда так делают" — и каждый раз начиналось одно и то же: перезапустить
пайплайн, посмотреть лог, развести руками. В какой-то момент захотелось не
просто перезапускать, а понять, *какие именно* тесты у нас флакуют и
насколько сильно — и не вручную листать историю CI, а прогнать всё локально
N раз и получить сводку.

Заодно это хороший повод покопаться в JUnit 5 — написать собственный
`TestWatcher`, погонять `Launcher` API напрямую и подёргать порядок
выполнения тестов.

## Как это работает

1. `FlakyTestRunner` запускает демо-сьют (`flakeradar.demo`) N раз через
   JUnit Platform Launcher.
2. Расширение `FlakinessExtension` (`TestWatcher`) на каждый тест в каждом
   прогоне записывает исход (pass/fail/aborted) и длительность.
3. `StatsAggregator` сворачивает всё это в статистику по тесту: процент
   флакания, pass/fail/aborted, min/avg/max время.
4. `CorrelationAnalyzer` строит для каждого теста бинарный вектор "упал/не
   упал" по прогонам и считает корреляцию Пирсона между парами тестов — так
   находятся тесты, которые ломаются вместе (например, из-за общего
   состояния).
5. `HtmlReportGenerator` рендерит всё это в один HTML-файл без внешних
   CSS/JS.

## Как запустить

Нужны Java 17+ и Maven (или `./mvnw`, если своего Maven под рукой нет).

```bash
./mvnw test-compile exec:java@run-detector -Druns=30
```

По умолчанию (`-Druns` не указан) делается 20 прогонов. Результат —
`target/flake-report/index.html`.

Обычный `mvn test` демо-сьют не трогает — он специально флакует, поэтому
запускается только через `exec:java@run-detector`, отдельно от unit-тестов
самого инструмента (`flakeradar.core`, `flakeradar.report`).

## Пример отчёта

Готовый пример (30 прогонов демо-сьюта) лежит в
[`docs/example-report.html`](docs/example-report.html) — можно открыть
прямо в браузере без сборки проекта.

В демо-сьюте специально собраны разные виды флакания:

- `CalculatorTest` — стабильный, контрольная группа;
- `RandomScoreTest` — без фиксированного seed, падает примерно в 30%
  прогонов;
- `SlowExternalServiceTest` — имитация внешнего вызова со случайной
  задержкой и плотным таймаутом;
- `SharedCounterOrderTest` — два теста с общим статическим состоянием и
  случайным порядком выполнения — падает то один, то другой, и в отчёте
  это видно как коррелирующая пара.

## Известные ограничения

- Прогоны идут в одном процессе и последовательно — для большого набора
  тестов N=30+ может занимать заметное время.
- Корреляции считаются только по факту падения (1/0), без учёта *причины*
  падения — два теста, падающих по совершенно разным причинам в одних и тех
  же прогонах, всё равно попадут в одну пару.
- Порог корреляции (`|r| >= 0.5`) и порог "плотного" таймаута в демо-тесте
  подобраны на глаз, не статистически обоснованы.
