# FlakeRadar — дизайн

Дата: 2026-06-12

## Идея

Инструмент для обнаружения нестабильных (flaky) тестов: запускает тестовый
набор N раз подряд в одном процессе, через собственное расширение JUnit 5
(`TestWatcher`) собирает статистику по каждому тесту и генерирует простой
HTML-отчёт с вероятностью флакания, временем выполнения и тестами, которые
падают вместе (корреляция).

Проект — портфолио-кейс, демонстрирующий владение JUnit 5 internals,
test-инфраструктурой и умение работать с flaky-тестами.

## Стек

- Java 17, Maven
- JUnit 5 (Jupiter + Platform Launcher API)
- exec-maven-plugin для запуска main-класса
- Без внешних UI-зависимостей — отчёт на чистом HTML/CSS

## Архитектура

Один Maven-модуль. Код инструмента — в `src/main/java`, демо flaky-тесты и
unit-тесты самого инструмента — в `src/test/java`, в разных пакетах:

- `flakeradar.demo` — демо-тесты, которые гоняет сам инструмент
- `flakeradar.core` / `flakeradar.report` — unit-тесты логики инструмента
  (не запускаются раннером, только обычным `mvn test`)

### Компоненты (src/main/java)

1. **`FlakinessExtension`** — реализует `TestWatcher`,
   `BeforeTestExecutionCallback`, `AfterTestExecutionCallback`. Для каждого
   теста в каждом прогоне пишет в `ResultsCollector`: id теста,
   отображаемое имя, номер прогона, исход (pass/fail/aborted), длительность
   в мс, сообщение исключения при падении.

2. **`ResultsCollector`** — потокобезопасный singleton-накопитель списка
   `TestExecutionRecord`. Имеет `reset()` между прогонами не нужен — просто
   копится список с полем `runIndex`.

3. **`FlakyTestRunner`** (main) — читает число прогонов N из аргумента
   командной строки / системного свойства `runs` (по умолчанию 20). N раз
   строит `LauncherDiscoveryRequest` с `selectPackage("flakeradar.demo")` и
   вызывает `launcher.execute(request)`, выставляя текущий `runIndex` в
   `ResultsCollector` перед каждым прогоном. Печатает прогресс в консоль.
   После всех прогонов вызывает `StatsAggregator` и
   `CorrelationAnalyzer`, передаёт результат в `HtmlReportGenerator`.

4. **`StatsAggregator`** — группирует записи по `testId`, считает:
   - количество прогонов, pass/fail count
   - `flakinessRate = min(passCount, failCount) / totalRuns` (0%, если тест
     всегда проходит или всегда падает)
   - min/avg/max длительность в мс

5. **`CorrelationAnalyzer`** — для каждого теста строит бинарный вектор
   длины N (1 = fail, 0 = pass/прочее). Для каждой пары тестов, у которых
   оба вектора имеют ненулевую дисперсию, считает коэффициент корреляции
   Пирсона. В результат попадают пары с `|r| >= 0.5`, отсортированные по
   убыванию `|r|`.

6. **`HtmlReportGenerator`** — рендерит `target/flake-report/index.html`:
   шапка с параметрами запуска (N, дата), сводные карточки (всего тестов,
   из них flaky / стабильных / всегда падающих), таблица тестов
   (сортировка по `flakinessRate` убыв., CSS-бар по % флакания, min/avg/max
   время), секция "Тесты, которые падают вместе" с таблицей пар и `r`.
   Никаких внешних JS/CSS библиотек — всё инлайново в одном файле.

### Демо-сьют (src/test/java/flakeradar/demo)

- `CalculatorTest` — стабильный, контрольная группа
- `RandomScoreTest` — `new Random()` без seed, assert на пороговое
  значение → падает примерно в 30% прогонов
- `SlowExternalServiceTest` — имитация внешнего вызова через `Thread.sleep`
  с плотным таймаутом → иногда не укладывается по времени
- `SharedCounterOrderTest` — два метода с общим статическим состоянием +
  `@TestMethodOrder(MethodOrderer.Random.class)` → флак из-за порядка
  выполнения; эта пара методов должна попасть в секцию корреляций

## Обработка ошибок / краевые случаи

- N <= 0 → понятная ошибка в консоли, выход с кодом 1, отчёт не строится
- Если ни один тест не найден — отчёт со сводкой "0 тестов" без падения
- Пары с нулевой дисперсией (тест всегда проходит/всегда падает) не
  участвуют в расчёте корреляций — деление на ноль исключается проверкой

## Тестирование самого инструмента

Юнит-тесты на `StatsAggregator` и `CorrelationAnalyzer` на синтетических
наборах `TestExecutionRecord` (без реального запуска JUnit) — проверяют
расчёт `flakinessRate`, мин/среднее/макс и корреляции на известных
векторах, включая краевые случаи (нулевая дисперсия).

## Запуск

```
mvn test-compile exec:java@run-detector -Druns=30
```

(`exec-maven-plugin`, execution `run-detector`, `classpathScope=test`).
Результат — `target/flake-report/index.html`. В `docs/example-report.html`
коммитим заранее сгенерированный пример отчёта для просмотра без запуска.
